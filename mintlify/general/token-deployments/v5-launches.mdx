---
title: "V5 Launches"
---

V5 tokens charge a tax on each buy and sell. The tax pays the protocol fee, the creator rewards and, if the creator turns them on, holder dividends, burns and an integrator share.

## Deploy with the API

Use `POST /api/tokens/deploy` with `protocol: "v5"` and `tax: { buyFee, sellFee }`. The other token fields and partner authentication work as for v4 launches. See [Deployment](/api-reference/authenticated/deployment).

* `buyFee` and `sellFee` give the total trade tax in percent, including the protocol fee.
* Optional tax fields: `dividends`, `burn`, `minimumDividendHolding`, `antiSnipeEnabled`, `integrator` and `metadataEditable`.
* `dividends`, `burn` and the integrator `share` are percentages of the tax after the protocol fee. Together they must not exceed 100.
* `minimumDividendHolding` is a whole-token decimal string: the smallest balance that earns dividends.
* `integrator: { address, share }` gives an integrator part of the tax. The default share is 0.
* `metadataEditable` (default `true`) lets the creator change the image and metadata after launch, and verify the token.
* Use `dryRun: true` to simulate a launch without deploying.

The `/api/tokens/deploy/v4` route accepts v4 launches only.

## Launch policy

`GET /api/metadata/factories` returns the current V5 policy: `launchCreationEnabled`, the rate bounds, the protocol fee, the sniper tax and the minimum dividend holding.

A V5 launch needs an active factory with `launchCreationEnabled` set to true. When it is false (launches are not open yet, or the owner paused them), the deploy returns 400 with "V5 launches are not open yet."

## Pools and rewards

* `pool.pairedToken` can be WETH (for an ETH pair) or USDC.
* V5 rejects v4 fees, other pool settings, vaults, airdrops and pool extensions.
* A Droid launch (`agent` with `legionFundingRecipient`) needs the USDC pair, as on v4.
* Reward recipients are paid in the pair token: native ETH for an ETH pair, USDC for a USDC pair.

## Fees and claims

The FeeEscrow holds one balance per recipient and currency for all of that recipient's V5 tokens, and a claim pays the whole balance. The fees and claimed-fees APIs split each claim by token. Creator earnings show the whole balance that a claim pays.

## Managing a V5 token

clanker-sdk does not support V5 yet. Use the token admin page at `https://clanker.world/clanker/<token address>/admin` to:

* claim fees
* update the image and metadata
* verify the token
* change the reward recipients and admins

A V5 token has no `verify()` function. To verify it, the current creator calls the factory's `updateTokenExtraMetadata(token, "verified", "true")`. Only the exact value `true`, written after launch, shows the Verified badge. A value set in the launch metadata does not count.
