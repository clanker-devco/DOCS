---
title: "Extensions"
---

Extensions are contracts that add functionality to the Clanker v4 token deployment process.

## How extensions work

During deployment, an extension can request a portion of the token's supply and an amount of ETH via `msg.value`, and can take actions on the token's deployed pool. For example, extension code can add unlocked liquidity to the pool, distribute tokens, or make swaps on the deployed pool.

The supply requested by extensions is taken from the amount that would otherwise go into the pool's initial liquidity positions. Up to 90% of the token supply can be allocated to extensions. The ETH requested by all extensions must sum to the `msg.value` passed into `deployToken()`.

## Configuring an extension

To deploy a token with an extension, add an `ExtensionConfig` struct to the `DeploymentConfig`'s list of extensions. The `ExtensionConfig` struct has this shape:

```solidity
struct ExtensionConfig {
    address extension; // address of the deployed extension, must be allowlisted on the factory
    uint256 msgValue; // the `msg.value` to send to the extension
    uint16 extensionBps; // the portion of the token supply to be allocated to the extension
    bytes extensionData; // additional data to be passed to the extension, specific to the extension being used, normally a struct
}
```

Extensions must be allowlisted by the Clanker team before they can be used on the factory, and we reserve the right to remove extensions.
