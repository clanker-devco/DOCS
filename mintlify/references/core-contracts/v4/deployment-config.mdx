This page describes the `DeploymentConfig` struct you pass to the Clanker v4 factory's `deployToken()` function.

## Token deployment

Tokens are deployed through the permissionless `deployToken()` function on the Clanker factory. All fields must be filled out. Each section below explains its part of the config.

```solidity
/**
* Deployment function for new Clanker token launches. Callable by anyone.
**/
function deployToken(DeploymentConfig memory deploymentConfig)
        external
        payable
        returns (address tokenAddress);

/**
* Configuration settings for token creation. Explanation of fields defined below.
*/
struct DeploymentConfig {
    TokenConfig tokenConfig;
    PoolConfig poolConfig;
    LockerConfig lockerConfig;
    MevModuleConfig mevModuleConfig;
    ExtensionConfig[] extensionConfigs;
}

struct TokenConfig {
    address tokenAdmin;
    string name;
    string symbol;
    bytes32 salt;
    string image;
    string metadata;
    string context;
    uint256 originatingChainId;
}

struct PoolConfig {
    address hook;
    address pairedToken;
    int24 tickIfToken0IsClanker;
    int24 tickSpacing;
    bytes poolData;
}

struct LockerConfig {
    address locker;
    // reward info
    address[] rewardAdmins;
    address[] rewardRecipients;
    uint16[] rewardBps;
    // liquidity placement info
    int24[] tickLower;
    int24[] tickUpper;
    uint16[] positionBps;
    bytes lockerData;
}

struct ExtensionConfig {
    address extension;
    uint256 msgValue;
    uint16 extensionBps;
    bytes extensionData;
}

struct MevModuleConfig {
    address mevModule;
    bytes mevModuleData;
}
```

## Token Config

These parameters are required for token creation:

| Parameter            | Description                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `tokenAdmin`         | The address that manages the token's admin rights.                                         |
| `name`               | Token name.                                                                                |
| `symbol`             | Token symbol.                                                                              |
| `salt`               | Address salt value that allows token address customization.                                |
| `image`              | Token image. The `tokenAdmin` can update this.                                             |
| `metadata`           | Token metadata. The `tokenAdmin` can update this.                                          |
| `context`            | Additional token context with information about who deployed the token. This is immutable. |
| `originatingChainId` | Chain ID where the token's supply is deployed.                                             |

Supply is set to 100 billion tokens with 18 decimals.

## Pool Config

These parameters are required for pool creation:

| Parameter               | Description                                                                                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hook`                  | The address of the hook to use for the pool. Must be an allowlisted hook on the factory.                                                                                                          |
| `pairedToken`           | The address of the paired token.                                                                                                                                                                  |
| `tickIfToken0IsClanker` | The tick to start the pool at, as if the deployed token is `token0`. The deployment config always assumes the deployed token is `token0`; if it isn't, the implementation handles the conversion. |
| `tickSpacing`           | The tick spacing to use for the pool.                                                                                                                                                             |
| `poolData`              | Additional pool data, specific to the hook being used.                                                                                                                                            |

## Locker Config

In v4, lockers manage the placement of liquidity positions and the distribution of LP fees to reward recipients. Locker contracts collect the fees and route them to the ClankerFeeLocker contract for users to claim.

These parameters are required to set up the liquidity locker:

| Parameter            | Description                                                                                                                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `locker`             | The address of the locker to use for the pool. Must be an allowlisted locker on the factory for the target pool.                                                                                |
| `rewardAdmins[]`     | The addresses of the admins who can modify the reward recipient at their matching index.                                                                                                        |
| `rewardRecipients[]` | The addresses of the recipients who receive the portion of the LP fees at their matching index.                                                                                                 |
| `rewardBps[]`        | The portion of the LP fees distributed to each recipient, in basis points. Must sum to 10,000.                                                                                                  |
| `tickLower[]`        | The lower tick for a liquidity position.                                                                                                                                                        |
| `tickUpper[]`        | The upper tick for a liquidity position.                                                                                                                                                        |
| `positionBps[]`      | The portion of the pool's allocated token supply used for a liquidity position, in basis points. Must sum to 10,000.                                                                            |
| `lockerData`         | Additional data passed to the locker, specific to the locker being used. See [ClankerLpLockerFeeConversion](/references/core-contracts/v4/fee-management-contracts/clankerlplockerfeeconversion) for how to fill this out. |

### Rewards

Rewards are a tuple of `rewardAdmin`, `rewardRecipient`, and `rewardBps`. The `rewardRecipient` receives the trading fees in the ClankerFeeLocker and can be updated by the `rewardAdmin`. The `rewardBps` is the recipient's portion of fees, out of 10,000. The total reward basis points must equal 10,000. The reward BPS split can't be changed after token deployment, and a maximum of 7 reward recipients are allowed per deployment.

### Liquidity positions

Liquidity positions are a tuple of `tickLower`, `tickUpper`, and `positionBps`. The `tickLower` is a position's lower tick and the `tickUpper` is its upper tick. Both assume the deployed token is `token0`, like the pool's starting tick. The `positionBps` array determines how the pool's token allocation is split among positions.

All tick ranges must be equal to or higher than the `tickIfToken0IsClanker` value, but are otherwise only constrained by normal tick rules. Positions don't have to be contiguous and can overlap.

## Extension Config

Extensions are contracts that add functionality to the token deployment process. See [Extensions](/references/core-contracts/v4/extensions) for more.

These parameters are required for each extension:

| Parameter       | Description                                                                           |
| --------------- | ------------------------------------------------------------------------------------- |
| `extension`     | The address of the extension to use. Must be an allowlisted extension on the factory. |
| `msgValue`      | The `msg.value` to send to the extension.                                             |
| `extensionBps`  | The amount of the token supply allocated to the extension, in basis points.           |
| `extensionData` | Additional data passed to the extension, specific to the extension being used.        |

If the `msg.value` passed into `deployToken()` doesn't match the sum of the extensions' `msgValue`, the deployment reverts. Up to 90% of the token supply can be allocated to extensions.

## MEV Module Config

These parameters are required for the MEV module:

| Parameter       | Description                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `mevModule`     | The address of the MEV module to use for the pool. Must be an allowlisted MEV module on the factory. |
| `mevModuleData` | Additional data passed to the MEV module, specific to the MEV module being used.                     |
