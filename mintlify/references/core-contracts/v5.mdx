---
title: "v5"
---

Clanker v5 deploys tokens that charge a buy and sell tax instead of an LP fee. The tax pays the Clanker fee and the creator's reward recipients, and the creator can also send part of it to holder dividends, a burn and an integrator. Clanker v5 is live on Base. See [v5 Deployments](/general/token-deployments/v5-deployments) for how v5 tokens work and how to deploy one.

The v5 contracts are not upgradeable.

The factory links to the others: `hook()`, `dividendDeployer()` and `announcementRegistry()` on the factory, and `feeEscrow()` on the hook, return the addresses above. All v5 addresses are also listed in [Deployed Contracts](/references/deployed-contracts).

### Factory

The factory deploys each v5 token, creates its Uniswap v4 pool with the hook, and places the whole supply in the pool as single-sided liquidity. It stores the launch policy that every new launch must fit, and the creator rights of every token it launched.

A v5 token is an ERC-20 with 18 decimals and a fixed supply, 1 billion tokens under the current settings. It has no owner, minter, pauser or upgrade path. Every v5 token address ends in `cccc`. A launch is rejected when the predicted address does not, so the launch salt is chosen to give such an address.

**Launch functions**

```solidity
// Deploys a token and its pool. msg.value must equal nativeLaunchFee().
function createLaunch(LaunchParams calldata launchParams)
    external payable returns (address token, bytes32 poolId);

// Deploys a token and makes a first buy in the same transaction.
function createLaunchAndBuy(LaunchParams calldata launchParams, LaunchBuyParams calldata launchBuyParams)
    external payable returns (address token, bytes32 poolId, uint256 amountOut);

// Returns the rates that a tax configuration gives under the current policy, and whether it enables dividends.
function previewTaxConfiguration(TaxConfiguration calldata configuration)
    external view returns (TaxConfigurationPreview memory);
```

`LaunchParams` holds the creator, up to 7 reward recipients (`feeSlots`), name, symbol, `tokenContractURI`, `creatorSalt`, the quote token, `expectedConfigVersion`, a `deadline`, `metadataEditable`, extra metadata keys and values, the `taxConfiguration`, the creator and integrator reward recipients, and `antiSnipeEnabled`.

* `expectedConfigVersion` must equal `configVersion()`. Any change to the launch settings increases the version, so a launch signed under older settings reverts with `StaleConfig`.
* `taxConfiguration` sets `buyTaxRate` and `sellTaxRate`, and the split of the tax after the Clanker fee: `creatorAllocationShare`, `burnAllocationShare`, `dividendAllocationShare` and `integratorAllocationShare`, which must add up to 100%. It also sets `minimumDividendHolding`. All rates and shares use a scale of `1e8` = 100%.
* The reward recipients' weights (`relativeWeightBps`) must add up to 10,000. One recipient can be marked as the creator's slot, which follows the creator rights.

**Creator functions**

The current creator of a token can call:

| Function                                                 | Purpose                                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------------ |
| `updateTokenExtraMetadata(token, key, value)`            | Sets a metadata value. `("verified", "true")` verifies the token         |
| `updateTokenName`, `updateTokenSymbol`, `updateTokenContractURI` | Changes the token's name, symbol or metadata URI                 |
| `setCreatorFeeRecipient(token, newRecipient)`            | Changes the recipient of the creator's reward slot                       |
| `proposeCreatorRightsTransfer(token, newCreator)`        | Starts a two-step transfer of the creator rights                         |
| `cancelCreatorRightsTransfer(token)`                     | Cancels a pending transfer                                               |
| `safeTransferCreatorRights(token, receiver, data)`       | Transfers the creator rights to a contract that confirms the transfer    |

The proposed creator completes a transfer with `acceptCreatorRightsTransfer(token)`. The metadata functions work only on tokens launched with `metadataEditable` set to `true`.

### Hook

The hook is the Uniswap v4 hook of every v5 pool. Only the factory can create a pool with it.

* **Tax**: on every swap, the hook takes the buy or sell tax. The Clanker fee, creator, dividend and integrator shares are taken in the quote currency and credited in the FeeEscrow. The burn share is taken in the launched token and credited in the FeeEscrow to the dead address `0x000000000000000000000000000000000000dEaD`.
* **Locked liquidity**: the hook places the launch liquidity itself and blocks every liquidity add and removal, so the liquidity can never be removed.
* **Frozen terms**: each pool keeps the tax, split and policy it launched with. Later policy changes apply only to new launches.
* **Sniper fee**: on a launch with the sniper fee on, the total fee starts at the policy's starting rate and falls linearly to the normal tax over the sniper window. The extra fee goes to Clanker. Exact-output swaps revert during the window.
* **No eligible holders**: when a trade's dividend share finds no eligible holder, it is credited to the Clanker fee recipient.

| Function                                            | Purpose                                                                         |
| --------------------------------------------------- | ------------------------------------------------------------------------------- |
| `poolConfig(poolId)`                                | The pool's token, quote token, creator, recipients, launch time and frozen tax  |
| `poolFeeSlots(poolId)`                              | The reward recipients, their admins and weights                                 |
| `effectiveFeeRates(poolId, isBuy)`                  | The current rates for a buy or a sell, including any sniper fee, and whether exact-output swaps are blocked |
| `updateFeeSlotRecipient(poolId, slotIndex, newRecipient)` | Changes a recipient. Callable by that slot's admin                        |
| `updateFeeSlotAdmin(poolId, slotIndex, newAdmin)`   | Changes a slot's admin. Callable by that slot's admin                           |

The creator's slot is not changed through the hook. It follows the creator rights on the factory.

**Integrator consent**: when a launch names an integrator that is a contract, the hook asks it once through `launchConsent(LaunchContext)`. A reply of `bytes4(keccak256("LAUNCH_REJECTED"))` blocks the launch. Any other reply lets it go ahead, and the accepting reply (the function's selector) emits `LaunchConsented`. Wallet integrators are not asked.

**Events**

| Event                                                         | Emitted when                                                  |
| ------------------------------------------------------------- | ------------------------------------------------------------- |
| `Trade(poolId, executor, referrer, quoteCurrency, quoteFeeAmount, comment)` | On every swap in a v5 pool                      |
| `ProtocolFeeCredited`, `AntiSnipeFeeCredited`                 | The Clanker fee or sniper fee of a swap is credited           |
| `CreatorTaxCredited(poolId, recipient, currency, amount)`     | A reward recipient's share is credited                        |
| `DividendTaxCredited`, `DividendTaxRedirected`                | The dividend share is credited, or sent to Clanker when no holder is eligible |
| `BurnTaxCredited`, `IntegratorTaxCredited`                    | The burn or integrator share is credited                      |
| `PoolRegistered`, `FeeSlotCreated`, `IntegratorAttributed`, `Seeded` | A pool is set up at launch                             |
| `FeeSlotRecipientUpdated`, `FeeSlotAdminUpdated`, `CreatorRightsUpdated` | Recipients or creator rights change                |

### FeeEscrow

The FeeEscrow holds every reward that v5 pools credit. It keeps one balance per recipient and currency, for all of that recipient's v5 tokens, and a claim pays the whole balance. The currency is the zero address for native ETH.

```solidity
// Callable by anyone. Pays the recipient's whole balance in `currency` to the recipient.
function claimFor(address recipient, address currency) external;

// Pays the caller's whole balance in `currency` to `destination`.
function claimTo(address currency, address destination) external;

// The claimable balance of a recipient in a currency.
function owed(address recipient, address currency) external view returns (uint256);
```

Only the hook can credit balances. Events: `Credited(recipient, currency, amount)` and `Claimed(recipient, currency, destination, amount)`.

### Dividend Deployer

The Dividend Deployer creates the dividend contract of a token that pays holder dividends, in the token's launch transaction. Only the factory can call it.

Each dividend contract tracks the balances of eligible holders and pays their dividends in the pair token. For an ETH pair, dividends are held as WETH and can be paid as native ETH. The factory owns every dividend contract.

| Function on a dividend contract                         | Purpose                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------- |
| `withdrawableDividendOf(holder)`                        | The holder's unclaimed dividends                              |
| `accumulativeDividendOf(holder)`                        | All dividends the holder has earned                           |
| `withdrawnDividends(holder)`                            | Dividends the holder has claimed                              |
| `excludedFromDividends(holder)`                         | Whether the holder is excluded                                |
| `receiverOf(holder)`                                    | The address that receives the holder's dividends              |
| `withdrawDividendsFor(holder, unwrapWrappedNative)`     | Claims the holder's dividends. Callable by the holder or the Dividend Claim Helper |

A claim emits `DividendPaid(token, holder, receiver, amount)`. `dividendOf(token)` on the factory returns a token's dividend contract.

### Dividend Claim Helper

The Dividend Claim Helper claims the caller's dividends from several v5 tokens in one transaction.

```solidity
struct Claim {
    address token;
    bool unwrapWrappedNative; // pay native ETH instead of WETH for an ETH pair
}

// Up to 64 tokens per call. Each token appears once.
function claimDividends(Claim[] calldata claims) external returns (uint256 paidCount, bool[] memory paid);
```

It emits `DividendsClaimed(holder, requestedCount, paidCount)`.

### Announcement Registry

The Announcement Registry records announcements from a token's creator to its holders. The factory registers each token at launch. Only the token's current creator can post, and each announcement ID can be used once per token.

```solidity
function postAnnouncement(address token, bytes32 announcementId, string calldata description, string calldata announcementURI) external;
```

It emits `AnnouncementPosted(token, creator, announcementId, description, announcementURI)`.

## Launch policy

The launch policy sets the limits and fees that every new launch must fit. Read it with `taxPolicy()` on the factory, or from `taxPolicy` in `GET https://www.clanker.world/api/metadata/factories`. Rates use a scale of `1e8` = 100%, so `1000000` is 1%.

| Field                                        | Meaning                                                                      | Current value on Base |
| -------------------------------------------- | ---------------------------------------------------------------------------- | --------------------- |
| `taxFeeBounds.minimumBuyTaxRate`             | Lowest buy tax                                                               | 1%                    |
| `taxFeeBounds.maximumBuyTaxRate`             | Highest buy tax                                                              | 10%                   |
| `taxFeeBounds.minimumSellTaxRate`            | Lowest sell tax                                                              | 1%                    |
| `taxFeeBounds.maximumSellTaxRate`            | Highest sell tax                                                             | 10%                   |
| `protocolFeeConfiguration.protocolTaxShare`  | Clanker's share of the tax                                                   | 10% of the tax        |
| `protocolFeeConfiguration.minimumProtocolFeeRate` | Lowest Clanker fee                                                      | 0.5% of the trade     |
| `protocolFeeConfiguration.maximumProtocolFeeRate` | Highest Clanker fee                                                     | 1% of the trade       |
| `protocolFeeConfiguration.protocolFeeRecipient`   | Receives the Clanker fee and the sniper fee                             | Set by the factory owner |
| `antiSnipeConfiguration.startTotalFeeRate`   | Total fee at launch when the sniper fee is on                                | 99%                   |
| `antiSnipeConfiguration.windowSeconds`       | Time for the fee to fall to the normal tax                                   | 20 seconds            |
| `minimumDividendHoldingRequirement`          | Lowest holder minimum a creator can set for dividends                        | 10,000 tokens         |

The Clanker fee is `protocolTaxShare` of the tax, kept between the minimum and maximum fee rate. For example, a 5% tax on a trade gives a Clanker fee of 0.5% of the trade, and a 10% tax gives 1%.

Other factory settings for new launches:

| Setting              | Current value on Base                                   |
| -------------------- | ------------------------------------------------------- |
| `launchSupply()`     | 1,000,000,000 tokens                                    |
| `nativeLaunchFee()`  | 0                                                       |
| `tickSpacing()`      | 200                                                     |
| `bandTemplate()`     | One band holding the whole supply, from the starting price up |
| Quote tokens         | Native ETH and USDC. See [Supported Quote Tokens](/references/supported-quote-tokens) |

## Administrative Permissions

The v5 contracts are not upgradeable. Each pool's tax, split and policy are fixed at launch, and no role can change them afterwards or remove its liquidity.

#### Factory

Role: `Owner` (two-step ownership transfer)

* Sets the launch policy for new launches: `setTaxPolicy()`, `setTaxFeeBounds()`, `setProtocolFeeConfiguration()`, `setAntiSnipeConfiguration()`, `setMinimumDividendHoldingRequirement()`.
* Opens or pauses new launches with `setLaunchCreationEnabled()`.
* Adds and removes quote tokens with `registerQuote()`, `unregisterQuote()` and their batch forms.
* Sets the starting price of a quote token with `setQuoteStartTick()`, and sets the price updater with `setPriceUpdater()`.
* Changes the supply, pool layout and launch fee of new launches: `setLaunchSupply()`, `setTickSpacing()`, `setBandTemplate()`, `setNativeLaunchFee()`.
* Sets the adapter used by `createLaunchAndBuy` with `setLaunchBuyAdapter()`.
* Sets the default dividend exclusions of new launches with `setDefaultDividendExclusion()`.
* Sets the Announcement Registry once with `setAnnouncementRegistry()`.
* Appoints and removes the creator admin: `transferCreatorAdmin()`, `cancelCreatorAdminTransfer()`, `revokeCreatorAdmin()`.

Role: `Owner` or `Creator admin`

On the dividend contract of any v5 token:

* Excludes or re-includes holders with `setLaunchDividendExclusions()`.
* Sets the address that receives a holder's dividends with `setLaunchDividendReceiver()`.
* Updates holders' recorded balances with `refreshLaunchDividendShares()`.
* Withdraws assets held by the dividend contract with `emergencyWithdrawDividendAssets()`.

Role: `Price updater`

* Updates the starting price of a registered quote token for new launches with `setQuoteStartTick()` and `batchSetQuoteStartTicks()`.

Role: `Current creator` (per token)

* Updates the token's metadata, if it launched with `metadataEditable` on.
* Changes the creator's reward recipient and transfers the creator rights.
* Posts announcements in the Announcement Registry.

#### Hook

The hook has no owner. Only the factory can register and seed pools, change the creator of a pool, run a launch buy and set the launch buy adapter. Each reward slot's admin can change that slot's recipient and admin.

#### No Administrative Permissions

Clanker has no administrative abilities on the following contracts:

* v5 tokens
* FeeEscrow
* Dividend Claim Helper
* Announcement Registry
* Dividend Deployer (only the factory can use it)
